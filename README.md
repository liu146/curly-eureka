# 城市天气与出行建议爬虫 Agent

> 网络爬虫技术课程大作业 · 刘志远 2024612065

一个"能自己查数据、自己算指标、自己给建议"的垂直领域 Agent：
爬取 12 个城市 24 个月的历史天气与未来 7 天预报，落库为 SQLite，
在数据之上提供**可解释的出行指数**，并由一个**工具调用型 Agent**回答
"周末去哪玩""要不要带伞""穿什么"等问题，所有结论都带可溯源引用。

## 1. 功能一览

| 模块 | 能力 |
|---|---|
| 采集 | 中国天气网 7 天预报 + 天气后报历史月度表；限速、重试、缓存、robots 校验、断点续爬、幂等入库 |
| 存储 | SQLite 单文件（`data/weather.db`），5 张表，支持增量更新与采集日志 |
| 分析 | 城市气候画像、月度气温趋势、降水频率、昼夜温差、冷暖距平、0–100 出行指数 |
| Agent | 意图识别 + 槽位抽取 → 工具调用 → 观测 → 反思补全 → 模板化作答；带执行轨迹与自检项 |
| 输出 | 6 张图表、统计 JSON/CSV、Markdown 出行简报、Word 实验报告 |

## 4. 快速开始

```powershell
# 1) 初始化数据库（写入 12 个城市）
python -m src.crawler.cli init-db

# 2) 采集：未来 7 天预报 + 24 个月历史（约 300 次请求，默认 1.2s 间隔）
python -m src.crawler.cli crawl-all

# 3) 统计分析与图表
python -m src.analysis.cli

# 4) 问 Agent
python -m src.agent.cli "北京这周末适合出去玩吗？需要带伞吗？" --trace

# 5) 评测（20 题）
python -m eval.run_eval

# 6) 生成 Word 报告
python build_report.py
```

也可以直接运行 `./run_all.ps1` 一次跑完 1–6 步（可选参数 `-SkipCrawl`、`-SkipReport`）。

### 采集命令补充

```powershell
python -m src.crawler.cli crawl-forecast --cities 北京,上海 --force
python -m src.crawler.cli crawl-history --start 2024-11 --end 2026-10
python -m src.crawler.cli status
```

`crawl_state` 表记录每个"城市 + 月份"的完成状态，中断后重跑会自动跳过已完成部分；
页面缓存位于 `data/cache/pages/`，历史页永久缓存，预报页 2 小时内复用。

## 5. Agent 用法

```powershell
# 单轮
python -m src.agent.cli "上海和杭州哪个更适合周末出游？"
# 显示规划、工具调用与自检
python -m src.agent.cli "下周三去成都，穿什么？" --trace
# JSON 输出（便于二次开发）
python -m src.agent.cli "北京今年夏天比去年热吗？" --json
# 交互模式，保留上下文（"那后天呢？"）
python -m src.agent.cli -i
```

支持的问法：

- 降水：`明天要带伞吗`、`广州会下雨吗`
- 穿衣：`下周三穿什么`、`这周末冷不冷`
- 择日：`未来一周哪天最适合出门`
- 对比：`上海和杭州哪个更适合周末出游`
- 气候：`今年夏天比去年热吗`、`最近天气反常吗`
- 简报：`帮我生成一份北京出行简报`

## 6. Agent 是怎么工作的

```
问题
 ├─ 规划器：意图识别（7 类）+ 槽位抽取（城市/日期/时长）
 │    └─ 生成有序的工具调用计划（每步带"为什么"）
 ├─ 执行器：调用 8 个只读工具，记录观测
 ├─ 反思器：检查城市覆盖、日期覆盖、引用完整性、数据新鲜度
 │    └─ 不满足时自动补调工具（最多 2 轮）
 └─ 组装器：用工具返回的数字填模板 → 结论 + 表格 + 建议 + 来源
```

关键设计：**答案里没有一个数字来自模型自由生成**。所有数值都由 SQL 查询与
`metrics.py` 计算得出，组装器只负责措辞；因此不会出现"幻觉气温"。
没有 API Key 也能完整运行——规划器是纯规则的，这也是本项目的离线兜底方案。

## 7. 出行指数模型

满分 100，从五个维度扣分，并返回扣分明细：

| 维度 | 规则（示例） | 最大扣分 |
|---|---|---|
| 气温舒适度 | 均温 16–26℃ 不扣分，偏离越多扣越多 | 35 |
| 降水 | 雨/雪 −18，暴雨/大雨 −25，阴 −6 | 25 |
| 风力 | ≥6 级 −12，5 级 −6，4 级 −2 | 12 |
| 昼夜温差 | >15℃ −12，>12℃ −8，>10℃ −4 | 12 |
| 极端温度 | 最高 ≥35℃ 或最低 ≤−10℃ | 16 |

等级：A ≥ 80，B ≥ 65，C ≥ 50，D < 50。

## 9. 合规说明

- 采集前读取 `robots.txt`：中国天气网 `Allow: /`；天气后报未提供可解析的 robots
  （返回 403），按 RFC 9309 的 4xx 语义视为"无限制"，仍主动限速。
- 默认 1.2 s/请求，失败指数退避，单任务串行，不并发压站。
- 只采集页面公开展示的天气数据，不下载、不传播任何图片或付费内容。
- 页面缓存 + 断点续爬，避免重复请求。

## 10. 常见问题

**Q：采集到一半断了怎么办？**
直接重跑 `crawl-all`，`crawl_state` 会跳过已完成月份，缓存也会复用。

**Q：页面改版了解析报错？**
`parsers.py` 会在找不到关键节点时抛出带城市名的 `ValueError`，并在 `crawl_log`
中记录 `fail`，不会静默写入脏数据。

**Q：没有网络能演示吗？**
可以。仓库自带 `data/weather.db`，分析和 Agent 全部离线可跑；重新采集则需要网络。
